# shots — IR 덱에 들어가는 실제 실행 화면

목업이 아닙니다. `game/web`을 띄우고 Playwright로 찍은 그대로이며,
`volt_ir_deck.py`가 여기서 읽어 씁니다.

| 파일 | 무엇 | 쓰이는 곳 |
| --- | --- | --- |
| `tap-btc.png` | Tap Trading · BTC 마켓 (원본) | 크롭 원본 |
| `tap-volt.png` | Tap Trading · VOLT 마켓 (원본) | 크롭 원본 |
| `death-full.png` | Death Fun · 버스트 직후 전체 화면 (원본) | 크롭 원본 |
| `hero-tap.png` | 위 VOLT 화면의 차트+격자 크롭 | 4쪽, 8쪽 |
| `market-btc.png` | 위 BTC 화면의 차트+격자 크롭 | 8쪽 |
| `hero-death.png` | 판 전체가 공개된 보드 크롭 | 5쪽 |
| `cover-band.png` | 표지·마무리 배경 띠 | 1쪽, 16쪽 |

두 가지가 캡션과 맞아야 합니다.

- **VOLT 마켓 화면은 외부 네트워크를 전부 차단한 채 찍었습니다.** 경로를
  브라우저가 직접 생성하기 때문에 그래도 그려집니다 — 4쪽 캡션이 주장하는
  내용이 이것입니다.
- **BTC 마켓 화면의 선은 브라우저가 거래소 소켓에서 직접 받은 체결가입니다.**
  서버의 `BINANCE_API_BASE`는 정산에만 쓰이므로 목 서버를 걸어도 차트에는
  영향이 없습니다. 8쪽의 "실시간 거래소" 라벨은 그 뜻입니다.

5쪽에 적힌 24 / 15 / 9 는 `death-full.png` 화면에서 그대로 읽은 값입니다.
MEDIUM은 6×6 격자에서 시드로 모양을 깎아내므로 판마다 칸 수가 다릅니다 —
이 라운드는 24칸이고, `DIFFICULTIES.medium.density = 0.62` 이므로
`round(0.62 × 24) = 15`가 해골, 나머지 9칸이 안전 타일입니다.
다시 찍으면 숫자도 같이 고쳐야 합니다.
